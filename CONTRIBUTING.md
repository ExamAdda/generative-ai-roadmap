## Before Contributing

1. Search existing issues and content to avoid duplication.
2. Use the topic or problem template.
3. Write original explanations; do not copy protected tutorials, examples, or problem statements.
4. Test every implementation with normal, boundary and edge cases.
5. State accurate time, auxiliary-space, latency, cost, and evaluation trade-offs when relevant.

## Naming Rules

- Use lowercase kebab-case for folders and Markdown files.
- Use descriptive names such as `rag-evaluation-basics` or `prompt-engineering-best-practices`.
- Keep one authoritative explanation per topic, project, or interview resource.
- Store code examples inside the relevant topic or project folder.
- Update `README.md` or `INTERVIEWS.md` when adding roadmap or interview content.

## Pull Request Checklist

- [ ] Links and Markdown render correctly
- [ ] Code compiles and tests pass
- [ ] Explanation and code agree
- [ ] Complexity is included
- [ ] Sources are cited when required
- [ ] Navigation indexes are updated
